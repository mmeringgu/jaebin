# 후생신보 제목 교정

## 라포르시안 순위 숫자 혼입도 함께 교정

라포르시안 등 NDsoft 매체의 많이 본 기사 링크는 순위 숫자(`.number`)와 실제 제목(`.auto-titles`)이 같은 링크 안에 있습니다. 목록 수집 시 순위 영역은 제외하고 제목 영역을 읽습니다. 제목 자체의 2.7조·2.6조·2개 등의 숫자는 보존합니다.

이미 저장된 라포르시안 기사 중 제목 앞에 순위로 의심되는 숫자가 있으면 원문 메타데이터와 대조해 표시 제목을 복원합니다. 임의로 숫자를 잘라내지 않으며, D1은 수정하지 않습니다. 기사 목록의 기존 자동 재조회로 복원 결과를 표시합니다.

2026-11-17 보완: `2내년부터…`처럼 순위 뒤 공백 없이 저장된 제목도 원문 확인 대상으로 포함합니다. 원문 조회 실패 시 화면이 재조회를 멈추던 문제도 수정했습니다. 실패 캐시(1분)가 만료된 뒤 다시 확인하도록 65초 간격으로 재조회하며, 처리 대기 중이면 기존 2초 간격을 사용합니다. 전체 자동 재조회는 최대 60회입니다. 원문 접속이 계속 차단되면 저장된 제목을 유지합니다.

## 현재 적용 방식: D1 변경 없이 조회할 때 복원

`cloudflare-upload/worker.js`를 기존 `smd-news` Worker의 Edit code에서 메인 JavaScript 파일 내용으로 교체하고 Deploy하면 됩니다. 이번 적용에는 아래의 D1 교정 도구와 SQL 실행이 필요하지 않습니다.

- 기사 목록 API는 캐시된 제목으로 먼저 응답하고, 원문의 `og:title` 또는 `twitter:title`에서 실제 제목을 백그라운드로 가져옵니다. 교정하거나 번역할 제목이 남아 있으면 화면이 2초 간격으로 최대 60회 재조회합니다.
- 실제 제목으로 복원한 뒤 키워드로 분류하며, 기사 목록·수집 관리·CSV·리포트 공통 조회에 적용합니다.
- 제목의 `[후생신보]`·`【후생신보】`·`［후생신보］`·`≪후생신보≫`·`《후생신보》` 매체 표기를 제거합니다.
- 복원한 제목은 D1 대신 Worker 메모리와 Cache API에 24시간 보관합니다.
- 원문 접속 실패 시 매체 표기만 제거한 기존 제목을 유지하고, 1분 후 조회부터 재시도합니다.
- 한 번에 최대 8개 기사를 처리하고 4개마다 캐시에 저장합니다. 한도를 넘은 기사는 화면의 다음 자동 조회에서 이어 복원합니다. `sub_read.html?uid=…` 등 옛 주소도 숫자 기사 주소로 통일해 조회합니다.

처음에는 기존 제목으로 목록이 먼저 표시됩니다. 배포 후 잠시 기다렸다가 새로고침해 기존 기사 제목을 확인합니다.

자동 재조회를 적용하려면 `static/articles.js`도 함께 배포해야 합니다. 최신 저장소를 받은 다른 장비에서 `npm.cmd run deploy`로 전체 프로젝트를 배포하는 방식을 권장합니다. 현재 장비에서 Cloudflare에 접속할 필요는 없습니다.

업로드 파일을 다시 만들 때는 `node scripts/build-cloudflare-upload.js`를 실행합니다. Cloudflare 로그인 없이 현재 `src/index.js`와 관련 모듈을 한 파일로 묶습니다.

## 선택 사항: D1 자체를 교정하는 이전 도구

아래 절차는 저장된 데이터 자체를 수정하려는 경우에만 사용합니다. 코드로 표시 제목만 교정할 때는 실행하지 않습니다.

후생신보 목록의 `dd.title a[href]`만 수집하며, 제목 앞의 `[후생신보]`·`【후생신보】`·`［후생신보］` 표기를 제거합니다. 이미 저장된 매체 표기도 기사 목록·수집 관리·CSV 공통 조회에서 제거합니다.

본문이나 요약문이 제목으로 저장된 기존 데이터는 원문의 `og:title` 또는 `twitter:title`과 대조해 교정해야 합니다. 표기만 지우는 것으로는 실제 제목이 복원되지 않습니다.

## 운영 반영

Cloudflare 로그인 후 프로젝트 폴더에서 실행합니다.

```powershell
npx.cmd wrangler login
npm.cmd test
node scripts/repair-whosaeng-titles.js
```

마지막 명령은 운영 D1의 후생신보 기사·후보를 읽고 원문 제목과 대조합니다. 기본 실행은 DB를 변경하지 않습니다. 다음 파일을 생성합니다.

- `.wrangler/title-repair/before.json`: 수정 전 ID·주소·제목
- `.wrangler/title-repair/review.json`: 변경 전후 제목 및 원문 조회 실패 목록
- `.wrangler/title-repair/repair.sql`: 제목만 바꾸는 SQL

교정 내역을 확인한 뒤 다음을 실행합니다.

```powershell
node scripts/repair-whosaeng-titles.js --apply
npm.cmd run deploy
```

`--apply`는 운영 DB와 원문을 다시 대조한 후 교정합니다. 원문 조회에 실패한 기사가 있으면 DB 반영을 중단합니다. 원문 확인 이후 제목이 바뀐 행은 덮어쓰지 않으며, 중요 표시·메모·수동 분류·본문 등은 보존합니다.

배포 후 `/api/articles`와 사이트를 새로고침해 후생신보 제목을 확인합니다.
